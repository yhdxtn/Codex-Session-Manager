# Codex Session Manager

Codex 会话查看、导出与跨电脑迁移工具。

Windows 本地桌面工具。默认读取 `%USERPROFILE%\.codex\`，也支持 `CODEX_HOME` 和界面中的目录选择。会话内容只在本机读取和导出，不调用 AI 服务。

## 启动

双击 `启动工具.bat`。脚本优先启动 `dist-v1.1.7`，然后尝试已有发行包；都不存在时会从源码启动。首次从源码启动需要 Python 3.10+ 和网络下载 PySide6、zstandard。已有发行包可在无 Python 环境的 Windows 机器运行。

会话列表与预览并排显示。单击会话行即可查看记录；可按来源筛选本机扫描或 ZIP 导入的会话，在预览中直接查看已导入的图片附件，点击其他附件可用系统默认程序打开。悬停标题可查看 ID、工作目录、来源、归档状态等完整元数据。搜索会在输入停顿后刷新，窗口大小和列表/预览分栏位置会在下次启动时恢复。筛选时若当前会话仍符合条件，会保留选中项和预览；否则会清空旧预览，避免误看不在结果中的会话。

启动后选择一个或多个会话，可按标题、ID、正文和工作目录搜索，筛选日期及归档状态，并在右侧预览。点击“导出所选”选择阅读版和格式。扫描与导出运行在后台线程，可取消；中途取消的会话目录会保留 `未完成.txt` 标记。

## 导出格式

- TXT、Markdown、HTML 和 JSON 都支持“纯聊天版”和“完整版”。纯聊天版仅含用户和助手消息；完整版增加工具调用、工具结果、状态及未知事件。
- HTML 是内嵌样式的静态离线页面，记录内容经过 HTML 转义，没有外部脚本或资源。
- 原始 JSONL / ZST 选项按字节复制原始 rollout 文件；它不应用脱敏。勾选时需要额外确认，归档输入仍以原 `.jsonl.zst` 保存。
- 单会话 ZIP 可移植包默认勾选，包含可再次导入的会话 JSON、会话关联附件和 `manifest.json`。批量选择时仍可为每条会话分别生成 ZIP。
- “导出全部迁移包”会把本机已扫描和已导入的全部会话及其关联附件合并到一个 ZIP。将该文件复制到另一台电脑，在那里选择“导入 ZIP”即可一次载入；目标电脑不需要 Codex 原始目录。迁移包不含 Codex 登录配置、原始数据库或原始 JSONL/ZST。
- 导入仅接受本工具 ZIP 中的 `聊天记录.json` 和它引用的附件，也支持整库迁移 ZIP；不会解压包中的其他文件。相同会话 ID 会跳过；导入后的会话仍可预览、搜索、筛选并再次导出。导入会话保存在 `%LOCALAPPDATA%\CodexHistoryViewer\imports`；附件哈希不符或缺失时会在读取状态中报告。
- 可选脱敏会替换常见 `password`、`token`、`api_key`、`secret`、Bearer 凭据和 PEM 私钥格式。它是启发式处理，不能保证发现所有敏感值。脱敏位置会以 `[已脱敏: …]` 标出。

## 跨电脑迁移

1. 在原电脑打开程序，点击“扫描 / 刷新”，再点击“导出全部迁移包”，把生成的 `.zip` 保存到桌面或其他方便传输的位置。
2. 通过 U 盘、局域网或你选择的文件传输方式，把这个 ZIP 文件复制到另一台电脑。
3. 在另一台电脑运行本程序，点击“导入 ZIP”并选择该文件。
4. 导入完成后，会话会出现在列表中；选中会话即可在程序内预览和搜索，关联附件也会随包导入。无需在目标电脑登录原电脑的 Codex 账号或找到 Codex 数据目录。

每个会话目录中的 `manifest.json` 包含工具版本、UTC 导出时间、会话来源路径、记录计数、重复条目计数、文件字节数与 SHA-256、缺失附件和读取错误。清单不计算自身哈希以避免自引用。批量导出另生成 `导出报告.json`。

## 当前数据兼容

本机已只读检查到以下结构：

- `sessions/YYYY/MM/DD/rollout-*.jsonl`：顶层记录由 `type`、`timestamp`、`ordinal`、`payload` 组成；正文在 `response_item`，工具结果和状态主要在 `event_msg`。
- `archived_sessions/rollout-*.jsonl.zst`：压缩的 JSONL，需 `zstandard`。
- `session_index.jsonl`：本机记录为 ID、线程名和更新时间索引；只补充标题/时间，不用作聊天正文。
- `history.jsonl`：只作为可能的辅助历史，不作为完整对话读取。
- `state_*.sqlite`：动态检查表和列后读取会话元数据。
- `thread_history_*.sqlite`：动态检查 JSON 条目表。若 rollout 文件缺失，可将其作为数据库回退来源；推理类条目会跳过。
- SQLite 以 `mode=ro` 打开后通过 SQLite Backup API 创建临时一致性快照，从而纳入已提交的 WAL 内容；快照放在系统临时目录，退出时清理，不修改源数据库。
- 附件只从 `attachments\<会话 ID>` 目录、记录中明确引用的 `attachments\<UUID>` 子目录及明确引用的文件读取；不会扫描或打包无关附件目录。

## 覆盖范围与限制

rollout JSONL 是消息、工具调用和状态的主要来源。`thread_history` 是投影数据，可能落后于正在写入的 rollout，也可能只保留部分会话条目；数据库回退不能据此宣称完整恢复。数据库中没有正文、源文件缺失或损坏时，工具会保留会话元数据并在状态、预览及清单标记“未找到”或错误。

阅读版会按条目 ID 或完全重复的记录去重；原始导出不改写原文件。已识别的 `reasoning`、加密思考内容和 `analysis` 阶段不导出。未知记录类型会保留为未知事件并计入读取报告。JSONL 逐行读取；界面正文搜索索引每个会话最多缓存 256,000 字符，超出部分仍可在导出和预览时读取，但不参加列表正文搜索。

会话附件目录按会话 ID 关联。记录中明确提到 `attachments\\<UUID>\\...` 的 UUID 子目录也会作为该会话附件读取；只检查被引用的子目录，不遍历打包其他附件。单条消息和附件之间没有可靠关联时，附件会被复制到会话目录，但消息不会被强行绑定到某个文件；缺失引用会报告。外部路径附件只在会话记录明确引用时尝试读取。

## 从源码启动和打包

也可以在命令行运行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

运行 `构建EXE.bat` 会安装打包依赖并生成 `dist-v1.1.7\CodexHistoryViewer\CodexHistoryViewer.exe`。EXE 不是代码签名发行版，首次运行时 Windows 可能显示常规下载文件提示。
